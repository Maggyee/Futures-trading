## 诊断数字如何解释

观察次数、形成时间去重数、触碰事件去重数、合约／日／方向组合数和成交数是不同单位。多个版本遇到同一机会，不能增加独立样本量；时间去重也不等于统计独立。

成本诊断中的目标空间是原训练目标比例与因果ATR／成本下限生成的机械价格尺度，分母包含成本下限，不能据此证明有足够未来有利空间。补充账本同时提供成本／原始训练目标跳数价格距离；两个目标尺度均不用未来极值，也不修改交易门槛。5分钟ATR上的较低比例没有沿用0.5阈值。宽止损使成本／初始风险变小，也不能解释为更划算。

费用沿用原有历史规范适用诊断和仅交易所费用的假设；账户额外加收仍未知。表中净额只对应这一模型成本口径。

最低资金需求为空仓下限；当前容量还受既有持仓、预约、每日开仓及整数手数限制。观察时容量计算先于同一分钟候选的优先级分配，最终拒绝须以 `signals`、`orders` 和 `events` 账本为准。单笔／组合风险使用初始资金与当前权益的较小值；仅靠账户浮盈不能解除初始资金不足。

互斥诊断按执行资料→行情条件→成本→持仓状态／入场截止→结构保护→账户容量的次序归类；另列所有重叠原因。这个顺序只是报告口径，不能解释为移除过滤后的新增成交。没有列出的阻碍也不代表已经接受订单；止损后禁入、事件消费及新触发以完整信号账本为准，成交价格和费用还在下一开盘复核。

例如，8月基准成本诊断包含17次行情合格观察，其中2次已经超过入场截止；可触发范围内仍是原漏斗的15次，其中14次未通过成本门槛。8月19日13:51的IM信号成本／1分钟ATR约0.2136，资金下限为1309507.12元，单笔风险与分组保证金同时拒绝。14:33和14:36的两次成本合格观察还受入场截止限制，不是新增可执行机会。

单笔初始价格风险R＝净额／（手数×初始止损价格距离×合约价值）；预算R的分母还包含原成本缓冲。R合计不是连续账户回报。匹配入场的金额差额按下式分解，新增与丢失的入场单列：

`(新手数−旧手数)×旧每手净额 + 新手数×(新每手净额−旧每手净额)`

这是账本归因，不能当作重新分配资金后的反事实模拟。额外双边1跳成本压力也只是保留原费用和退出路径的账本扣减，不是重新撮合。

恢复通过既有单方案入口按各自冻结配置准备9月数据，继续完整训练指纹检查。原`maximum_runs=24`对应的24组策略评估之外，另如实计入这1次失败初始化，共25次操作尝试；这是明确记录的初始化恢复例外，没有新增配置或据收益调参。原计划和本轮回放的55份研究源码冻结均不改写。

矩阵全部结束后仅修正`structure_followup.batch`：9月各方案由既有单方案路径独立准备裁剪数据，避免再次丢失训练指纹；7月、8月继续复用完整数值帧。其余54份研究源码、该文件中批量函数以外的代码、原计划及原实现冻结均保持原指纹。恢复声明同时列出入口修正前后指纹；新增回归测试先复现失败，再验证不同配置均保留完整训练资格。重新运行原冻结矩阵仍须匹配其归档源码，不能把后续入口修正伪称为旧回放实现。

全量测试458项通过；修改的Python文件通过Ruff，差异无空白错误。全仓Ruff仍有13个未修改文件的67项既有问题。24组实际回放的源码全部匹配原实现冻结；矩阵结束后未调整交易规则。

原发布清单中的671份研究结果文件全部保持原SHA256。旧 [publication_manifest.json](publication_manifest.json) 对源码的指纹对应旧版本；源码修改后整包校验会报告差异，不能覆盖旧清单来声称旧结果由新实现生成。
